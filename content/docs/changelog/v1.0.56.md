# v1.0.56 — An Advance Now Finishes Or Tells You Why Not

_Released 2026-08-12_

## What's New

**🛑 A season advance won't quietly half-finish anymore**

If Ball Boy can't create every game thread the week needs, the advance now **stops** instead of moving the season forward with threads missing.

You'll get a clear message naming which games couldn't get a thread, and the season stays exactly where it was. Nothing is half-done and nothing is thrown away — the threads that *were* created stay put, and when you fix the problem and run `/season advance` again, Ball Boy picks those same threads back up rather than making duplicates.

Why this changed: on August 9th an advance created four playoff threads and then froze partway through. The season ended up in a state where those four threads existed but the season didn't know about them. Previously the advance would push on through a thread it couldn't create; now a missing thread is a hard stop, because a week that's live with games nobody can find is worse than a week that hasn't started yet.

The same rule applies to `/season prepare_week` — it will tell you what failed instead of reporting everything is ready.

This only affects advances **you** trigger (the command or the `@everyone` trigger). Automatic advances driven by EA data are unchanged.

## Fixes

**🏆 CFP first-round games show the round, not the stadium**

A first-round playoff game's thread title was showing the higher seed's home venue — something like *"Missouri State (Campus Site)"* — because that's where the game is played, not a bowl name. First-round games now read **"CFP First Round"**. Quarterfinals, semifinals, and the championship are unchanged and still show their real bowl names.

**📅 `/schedule` names championship week properly**

Conference championship week showed up as *"Week 18"* in `/schedule`, even though the weekly announcement had been calling it *"SEC Championship"* all along. `/schedule` now uses the same name everywhere.

One place still lags: the schedule screen inside the Activity view. That's a separate fix and it's on the list.

## Under The Hood

**💾 Game thread IDs are saved the moment each thread is made**

Previously Ball Boy remembered every thread it created in one batch at the very end of the week's work. If something went wrong before the end, that whole batch was lost — which is exactly how those four playoff threads got orphaned.

Each thread's ID is now written down the instant the thread exists. That's what lets a retry adopt the threads already made instead of creating a second set, and it's the groundwork the stop-on-failure behavior above depends on.
