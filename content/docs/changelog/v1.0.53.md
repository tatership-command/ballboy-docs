# v1.0.53 — A Single Slow Discord Call Can No Longer Freeze The Bot

_Released 2026-08-10_

## Fixes

**🧊 One stuck request used to stop everything, everywhere**

On Saturday night a league advanced into the CFP quarterfinals. Ball Boy created all four game threads, then made one more routine call to Discord — adding a team owner to the last thread — and that call never came back.

Not slow. Never. It simply hung, with nothing to stop it.

Because a season advance holds a lock while it works, everything else queued up behind that one frozen call. Every command, in every league, on every server. The bot looked online and answered nothing until it was restarted.

**⏱️ Every Discord call is now on a clock**

Ball Boy's connection to Discord had no time limit of any kind — no connect limit, no read limit, no overall limit. A request that stalled could wait forever, and one did.

Every call now has bounded limits. The worst case is a single failed step that gets logged and skipped, instead of a bot that stops responding. That Saturday freeze would have been a one-line warning in the logs.

Rate limits are unaffected — Ball Boy still waits politely when Discord asks it to. The clock only applies to a request that has genuinely stopped responding.

**🔍 And we can now see what happened**

The reason the cause took so long to pin down is that Ball Boy was throwing away Discord's own diagnostics. Its logs went nowhere, and every failed request produced the same generic message with no detail.

That's fixed. Discord's internal rate-limit and connection diagnostics are now recorded, timed-out calls are tagged so they can be found instantly, and log entries are structured and searchable rather than plain text.

None of this changes anything you'll see in Discord. It's the difference between guessing at an outage and knowing what caused it — and it means the next problem gets diagnosed in minutes rather than hours.
